# LB-oculus · 陰陽眼

**跨專案的防幻覺工具鏈。** 讓 AI 的開發行為導向「更少 bug」，而不是導向「看起來完成」。

`LB-nexus · 律令` 管單一專案的關卡（SPEC → guard → contract → IMPL）。
這套管的是**所有專案共用的三條鐵律**，語言無關、專案無關。

---

## 為什麼需要它

2026-07-27 一輪對話，在一個專案裡抓出 31 個錯誤。**其中三分之一是當天現做的，而做的人正是在蓋防幻覺工事的那個 AI。**

分析那 31 筆之後，第一性原理只有一條：

> **Agent 會沿著「證據最容易製造」的方向走。**
> **架構的工作不是要求誠實，是讓造假比做對更貴。**

「看起來對」的信號是即時、確定、agent 自己就能製造的；
「實際對」的信號是延遲、不確定、要靠外部的。
梯度天生就指向造假。要求誠實是對抗梯度，會輸；改梯度才會贏。

三條鐵律各封掉一條最省事的假路。

---

## 三條鐵律

### 一 · 事實只能推導，不能複製

一個事實被抄寫一次，就等於預約了未來某天的一個謊。抄本不會跟著本體變，也沒人會回頭對。

> 真實案例：某支腳本的註解抄了另一支的常數，抄的值比真值大 15 倍 —— **而且兩邊變數名完全相同**。
> 這證明「統一術語」解決不了問題：病不在講法不同，在那個數字是打字打進去的、不是讀出來的。

### 二 · 0 信心路由

預設任何開發行為**第一次就有問題**，換一條路驗過才算數。**產出者不得自驗** —— 用產出它的同一條路去驗，等於沒驗。

> 真實案例：「驗過了」才推 commit，驗法是跑驗證腳本 —— 但那支腳本只驗 edges，node 欄位一個字都不看。
> 同角度驗 = 沒驗，一次放行三個假宣稱。

「路由」是重點：驗證要被**導到另一條路**，不是同一條再走一遍。

### 三 · debug 百科（coding 陰陽眼）

任何錯誤只要**被抓到一次** —— AI 抓、人抓、機器抓都算 —— 就立刻收錄。標記成本必須低到不會有人偷懶跳過。

**同樣重要的另一半：未收尾的事也要記。** 錯誤會叫，未完成不會叫；不會叫的才會變成大患。

## 安裝

```bash
git clone <repo> ~/Developer/LB-oculus
cd ~/Developer/LB-oculus && ./install.sh
```

symlink 安裝，不複製 —— 複製會產生第二份，兩份會漂移。

### Claude Code hooks（可選，但這是「落地」的關鍵）

install.sh 會放好 hook 檔，但**不會改你的 `~/.claude/settings.json`**。要啟用請自己加：

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Edit|Write|NotebookEdit",
        "hooks": [{ "type": "command", "command": "~/.claude/hooks/dbp-risk-gate", "timeout": 8 }] }
    ],
    "PostToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "~/.claude/hooks/dbp-autocapture", "timeout": 10 }] }
    ]
  }
}
```

兩個 hook 都**永遠 exit 0、永遠不擋**。會擋住工作的 hook 最後一定會被關掉。

> settings.json 在 session 啟動時載入，中途改不生效。

## 用法

```bash
dbp "一句話講清楚是什麼錯"        # 記一筆（唯一必填就是這句）
dbp "…" -w file.py:42 -t yaml,quoting -k machine
dbp fix <id> "後來怎麼解的"

dbp open                          # 未收尾清單（開場、收尾各跑一次）
dbp open "還沒驗證的事" -b "等服務重啟"
dbp done <id> "怎麼收的"

dbp risk <檔案>                   # 動手前：這個檔以前在哪摔過
dbp rules                         # 歸納：哪些類別重複出現
dbp sweep [目錄]                  # 清理：死引用 / 死 commit / 腐朽宣稱
dbp find <關鍵字> · dbp ls · dbp stats
```

### 完整迴路

```
錯誤 → 記錄 → 歸類 → 到閾值 → 變成機械檢查 → 該類永遠不再發生
```

**學習以「文件」收尾 = 沒落地。以「閘」收尾 = 落地了。**

`dbp rules` 跑出 `×2` 以上的類別，就不是零星 bug 了 —— 那是一個該從結構上關掉的類別。這時該做的是消滅整類，不是再修一個個案。

### 落地的操作定義

> **學到的東西必須在「動手的那一刻」出現，不是在「想起要查的那一刻」。**

那兩個時刻從不重合。實測：靠自律的記錄執行率只有 **25%**，而且全部發生在「停下來時」或「被罵時」。所以查詢也不能靠自律 —— 要交給 hook。

| | 落地了嗎 |
|---|---|
| 寫成文件 | ❌ 要人想起來讀 |
| 記進 log | ❌ 要人想起來查 |
| 手動 `dbp risk` | ❌ 同上 |
| **改檔當下自動跳出來** | ✅ 不需要想起來 |

## 設計約束（都是踩過才寫下來的）

- **永遠 exit 0。** 會中斷工作的記錄工具最後會被關掉。
- **沒事就完全安靜。** 每次都講話的東西會被當雜訊忽略。
- **假紅要當 P0 修。** 一個會誤報的閘會訓練人忽略所有閘，傷害大於價值。
  `sweep` 第一版誤報率 95%，是重大缺陷不是小問題。
- **抑制必須可見。** 每個豁免規則都是牆上的洞。洞可以有，但不能沒人知道它在。
  閘一旦擁有「什麼不算問題」的裁量權又沒人看著，它就從屠龍者變成龍。
- **規則必須能套在自己身上。** 豁免自己的規則系統就是惡龍。

## 已知還沒做到的

- `類別 → 閘` 這一步還是人手寫。真正落地應該是 `dbp rules` 到閾值時直接產出閘的骨架，人只審核。**這是離 AGI 最近也最遠的一格。**
- 概念型錯誤（判斷錯、假設錯）沒有退出碼，`dbp-autocapture` 抓不到，仍靠 agent 自律。
- 收斂指標（關掉幾類 vs 新開幾類）還沒實作。**沒有它，前面講的全部只是感覺。**
